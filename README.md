# Домики

Детская игра-конструктор: ставишь цветные кубики на полянку и строишь домики.
Работает в браузере планшета или компьютера, ничего устанавливать не нужно.

Открыть: https://salkutsan-collab.github.io/domiki/

Вход по семейному PIN. Текущий код: **2026**.

## Что внутри

- Полянка растет сама: как только кубик встал у края, трава прирастает - до 40 на 40 клеток.
- Высота до 12 кубиков, семь материалов: дерево, кирпич, окошко, крыша, камень, солнышко, листва
  (из листвы получаются деревья и кусты).
- Режимы: «Строить», «Убрать кубик», «Человечек», «Овечка», «Смотреть вокруг».
- Постройка сама сохраняется в браузере (кнопку «сохранить» нажимать не надо).

### Как крутить и приближать

- Режим «Смотреть вокруг»: ведешь пальцем вбок - полянка крутится, вверх-вниз - меняется наклон.
- Два пальца в любом режиме: щипок приближает, сдвиг переносит картинку.
- Мышь: колесо приближает, кнопки в углу поворачивают на четверть, значок цели возвращает вид как в начале.

### Как заглянуть внутрь домика

- Ползунок «Видно этажей» скрывает верхние ряды: видно комнату сверху, и скрытые ряды не мешают нажимать.
- Кнопка «Просветить стены» делает кубики полупрозрачными - домик видно насквозь.

### Жители и овечки

- Кнопка «Человечек»: нажми на травку - там поселится житель, сразу спросит имя.
  Нажатие по жителю в этом режиме меняет имя. Имя всегда видно над головой.
- Кнопка «Овечка»: нажми на травку - там будет пастись овечка.
- Житель ходит сам: по свободным клеткам, забирается на кубик выше и спускается на кубик
  ниже. Поэтому он входит в дом через дверной проем и гуляет по крышам, если построить
  ступеньки. В стену выше ступеньки не пойдет и сквозь потолок не пролезет.
- Овечка ходит только по траве и никуда не забирается.
- Ластик убирает и кубики, и жителей с овечками.
- Жителей и овечек - до 12 каждых. Они сохраняются вместе с домиком: имя, цвет рубашки
  и место, где их поселили. Куда фигурка ушла гулять - дело живое и не сохраняется.

### Как построить крышу

- Нажатие по верхней грани ставит кубик сверху.
- Нажатие по боковой стенке кубика ставит кубик рядом на той же высоте, даже если под ним пусто.
  Так собираются свесы, балконы и ступенчатая крыша - та же, что появляется по кнопке «Показать домик».

### Архив домиков (общий на все устройства)

- Кнопка «Мои домики» открывает архив: имя, кнопка сохранить, плитки с картинкой домика,
  датой и числом кубиков. Плитку можно открыть или убрать.
- Архив общий: сохранил на планшете - видно на телефоне и на компьютере.
- Недостроенная постройка на полянке остается своей на каждом устройстве, чтобы двое
  не перебивали друг друга.
- Открытый домик подписан в правом нижнем углу. Кнопка «Сохранить» обновляет именно его,
  «Сохранить как новый» кладет в архив копию.
- Без связи видны домики, сохраненные раньше (список хранится и в браузере).
- В архиве до 30 домиков.

### Клавиши на компьютере

Цифры 1-6 выбирают кубик, R поворачивает полянку, Ctrl+Z отменяет шаг.

## Как это устроено

Статическая страница: React плюс рисование на canvas, без сервера и без базы данных.
Постройка лежит в памяти браузера (localStorage), поэтому на каждом устройстве она своя.

Код разложен по смыслу:

- `src/world.ts` - кубики, границы полянки, рост травы, чтение и запись сохранения;
- `src/camera.ts` - проекция на экран, видимые грани кубика, пределы наклона и приближения;
- `src/render.ts` - рисование неба, травы, кубиков и подсветки;
- `src/hit.ts` - куда попал палец и куда встанет новый кубик;
- `src/use-gestures.ts` - касания, щипок, колесо мыши;
- `src/game.tsx` - состояние игры и панели.

- `src/archive.ts` - общий архив: подключение к базе, чтение списка, запись и удаление;
- `src/thumbnail.ts` - картинка постройки для плитки архива;
- `src/projects-panel.tsx` - окно «Мои домики»;
- `src/plural.ts` - согласование числа со словом.

Расчеты покрыты проверками: `npm test` (vitest). Проверяется поворот и наклон камеры,
подгонка вида под постройку, рост полянки, перенос старого сохранения, выбор клетки
для нового кубика и разбор записей архива.

## Общий архив: как устроен

Архив лежит в базе Firebase Realtime Database (проект `dima-707` - тот же, что у трекера
наклеек), в своей ветке `rooms/domiki-family-4k7m2p9x/projects`. Ветка выбрана внутри
`rooms` потому, что правила базы разрешают запись только там - менять правила в консоли
Firebase не нужно.

Вход анонимный, запись разрешена вошедшим. Ключи Firebase на статической странице
всегда открыты, это не пароль: кто найдет репозиторий, тот сможет читать и писать
в этот архив. Внутри только кубики, ничего личного.

Библиотека базы (около 95 КБ в сжатом виде) грузится отдельным куском через 1.2 секунды
после открытия страницы, чтобы игра появлялась сразу.

### Правила базы

Текст правил лежит в [firebase-rules.json](firebase-rules.json). Их надо вставить в консоли
Firebase: проект `dima-707` -> Realtime Database -> вкладка «Правила» -> «Опубликовать».

Что они делают:

- ветка архива домиков открыта только вошедшим (вход анонимный);
- домики лежат в ячейках `01`-`40`. Считать записи правила не умеют, а проверить имя
  ячейки умеют - так и получается предел в 40 домиков;
- запись проверяется по форме: только известные поля, название до 40 знаков, картинка
  до 40 КБ, кубики только под числовыми ключами до четырех цифр, координаты и высота
  в разумных пределах. Имя жителя обязательно и не длиннее 20 знаков. Все остальное
  база отклоняет;
- прежнее правило для остальных «комнат» сохранено - трекер наклеек работает как раньше.

Правила проверяются вместе с остальным кодом: `npm test` прогоняет их через targaryen
(тот же язык правил, что на сервере) и смотрит, что игра проходит, а мусор нет -
см. [src/rules.test.ts](src/rules.test.ts).

Чего правила не делают: они не мешают тому, кто нашел ключи в этом репозитории, читать
архив и менять в нем домики. От этого спасал бы только настоящий вход по паролю.
Правила закрывают другое - забить базу мусором и сломать заодно трекер наклеек уже нельзя.


## PIN

PIN проверяется прямо в браузере: в коде лежит не сам код, а его отпечаток
(SHA-256 от соли и цифр) - см. [src/access.ts](src/access.ts).
Это защита от случайного захода, а не настоящий замок: четыре цифры можно перебрать.
Внутри игры нет ничего секретного, только кубики.

### Как поменять PIN

1. Посчитать отпечаток нового кода (соль оставить ту же или задать новую):

```bash
node -e "const c=require('crypto');const salt='4f6ca04678d263bfc11f295f';const pin='НОВЫЙ_КОД';console.log(c.createHash('sha256').update(salt+':'+pin).digest('hex'))"
```

2. Вписать полученную строку в `PIN_HASH` в файле `src/access.ts`.
3. Закоммитить и запушить в `main` - страница пересоберётся сама.

После смены кода у тех, кто уже входил, вход спросится заново.

## Запуск у себя

```bash
npm install
npm run dev
```

Сборка статики - `npm run build`, результат в папке `dist`.

## Выкладка

Пуш в ветку `main` запускает GitHub Actions
([.github/workflows/deploy.yml](.github/workflows/deploy.yml)): сборка Vite и
публикация на GitHub Pages.

## Откуда взялось

Игра написана в Codex как проект на vinext (Next.js на Cloudflare Workers).
Для GitHub Pages сервер недоступен, поэтому проект переведён на статичную сборку Vite,
а проверка PIN перенесена с серверного маршрута `/api/unlock` в браузер.
Сама игра (`src/game.tsx`) и оформление (`src/globals.css`) перенесены без изменений.
